# 内置麦克风修复 — LatSOFAudio.kext

> 让联想小新 13 / Pro 13（Comet Lake + ALC257 + cAVS 1.8 DSP）上**从来没在 macOS 里活过的内置数字麦克风**，变成系统默认输入设备。
> 装好后：语音备忘录、QuickTime、Zoom、浏览器，所有 Core Audio 应用直接可用，**开机零操作**。

---

## 一、为什么必须额外装这个 kext

Comet Lake 之后的 Intel 笔记本，内置麦克风（PDM 数字麦）接在 CPU 内部的 **cAVS DSP** 上，而不是 Realtek 编解码器上。

`AppleHDA` 只驱动 codec 的模拟路径（扬声器 + 耳机），**从不初始化 DSP**。所以：

- ❌ 改 AppleALC 的 layout-id —— 没用
- ❌ 注入 DeviceProperties —— 没用
- ❌ 换任何 AppleHDA 补丁 —— 没用

Linux 的答案是 **SOF（Sound Open Firmware）**。本 kext 把这套能力整个搬进了 macOS 内核。

**它装在 `/Library/Extensions`（系统盘）而不是 EFI 里**，因为它是 AuxKC 内核扩展，不走 OpenCore 预注入。所以这份文件单独放在 `02-麦克风修复/` 里，拿到 EFI 后要手动装一次。

## 二、前置条件（缺一不可）

| # | 条件 | 怎么确认 |
|---|---|---|
| 1 | OpenCore 里 `Kernel → Quirks → DisableIoMapper = true` | 本包 config.plist **已经开好** |
| 2 | `boot-args` 含 `amfi=0x80` 与 `-lilubetaall` | 本包 config.plist **已经开好** |
| 3 | 能关闭内核扩展的用户批准 / 能重建 AuxKC | 见下方安装步骤 |
| 4 | 机器确实是 cAVS 1.x DSP + DMIC 挂在 DSP 上 | 本机是 `8086:02c8`（Comet Lake cAVS） |

> **第 1 条是硬门槛。** VT-d 开启时，DSP master 的 PCIe 取数在 macOS 的 VT-d 域里没有映射，会被静默丢弃 —— **连故障位都不置**，表现为麦克风永远静音且不报错。

## 三、安装步骤

```bash
# 1) 进到本目录
cd "Hackintosh-EFI-Lenovo-Xiaoxin13-Sequoia/02-麦克风修复"

# 2) 安装到系统扩展目录
sudo kmutil install --volume / --path-with-history ./LatSOFAudio.kext

# 3) 重建 AuxKC（辅助内核集合）
sudo kmutil create -z

# 4) 重启
sudo reboot
```

重启后约 3.5 秒，麦克风自动就位，不需要任何手动操作。

### 如果提示"需要用户批准"
开机时进入 **恢复模式**（开机按住 `Cmd+R`）→ 实用工具 → 启动安全性实用工具 →
允许加载第三方内核扩展；或在启动安全性里把安全策略降为"降低安全性"。

## 四、验证（装完必做）

### 1. 看内核日志

```bash
log show --last 2m --predicate 'eventMessage CONTAINS "LatSOF"'
```

期望看到这三行关键输出：

```
cl OK rom=0x00000005 (FW_ENTERED)   ← SOF 固件已进入
IPC ROUND-TRIP OK                    ← IPC  mailbox 通
Topology 8 OK                        ← topology 解析成功
```

### 2. 看 kext 是否加载

```bash
kmutil showloaded --list-only | grep -i latsof
```

期望：

```
com.hackintosh.LatSOFAudio (1.1.29)
```

### 3. 实际录音

打开「语音备忘录」录 5 秒，回放应有声音。
或者：系统设置 → 声音 → 输入，对着麦克风说话时**输入电平条应有跳动**。

## 五、排障

| 现象 | 原因 / 处理 |
|---|---|
| 完全没有 `LatSOF` 日志 | kext 没装进 AuxKC。重跑 `kmutil install` + `kmutil create -z`，确认已批准第三方扩展 |
| 有日志但 `rom != 0x00000005` | 固件没起来。多半是 `DisableIoMapper` 没生效，去 config.plist 复查 |
| 日志正常，系统也认设备，但 App 录不进去 | **TCC 隐私权限**没给。TCC 在 **App 启动时**评估：把 App 完全退出（Cmd+Q）再打开即生效 |
| 装完后开机卡死 / 播声音就冻机 | 早期 `hdaInit=3` 会劫持 AppleHDA 的命令环导致死锁。本版本默认 `hdaInit=0`，**完全不碰 AppleHDA**。若仍异常，加 boot-arg `latsof-auto=0` 禁用自动装载 |
| macOS 系统更新后麦克风失效 | 大版本更新会重建 KC，重新执行一遍第三节的安装命令即可 |

### 紧急停机（保险丝）

```bash
# 运行时临时关掉自动装载
sudo sysctl kern.latsof_lab="auto=0"

# 或持久化：在 boot-args 里加
latsof-auto=0
```

## 六、移植到其他机型

`NHLT` 文件是本机导出的 **ACPI NHLT 表**（6128 字节），是移植时判定 DMIC topology 的核心依据 —— 它描述了有几个 DMIC、采样率、链路参数。

拿到新机器后：

1. 在 Linux 下导出 NHLT（`/sys/firmware/acpi/tables/NHLT` 或用 acpidump）
2. 确认 `dmesg` 里有 `DMICs detected in NHLT tables: N`
3. 按对应 SoC 换 SOF 固件（Comet Lake 用 `sof-cml.ri`；ICL / TGL 需换固件与 topology）
4. 参考 [`源码文档/ADAPTING.md`](源码文档/ADAPTING.md)

> 本包 kext 内已嵌 SOF 固件（编译期 `.incbin`），**不需要额外下载固件文件**。

## 八、这套方案的五个技术要点（想深挖的看这里）

1. **VT-d 静默吞 DMA** —— DSP master 的 PCIe 取数在 macOS VT-d 域无映射，被丢弃且不置故障位。修：`DisableIoMapper = true`。
2. **BDL 地址截断** —— 关 VT-d 后 `IODMACommand` 的 32 位地址对 >4GB 物理页做 <4GB 重映射（`bdlBus ≠ bdlPhys`），ROM/loader 读到垃圾描述符。修：改用 64 位 BDL 寻址。
3. **绝不劫持 AppleHDA 命令环** —— 早期让 kext 代答 CORB/RIRB（hdaInit=3），会吞掉 AppleHDA 在飞的 verb（实测 58 条）→ 命令通道失同步 → 播放 StartIO 永久死锁 → **任何 App 出声即全机冻结**。生产档 `hdaInit=0`。
4. **开机自动装载** —— 重试引擎合成生产参数、DSP 初始化 defer 离开 matching 线程、自动 arm，开机 3.5 秒就位。保险丝：`latsof-auto=0`。
5. **TCC 麦克风权限** —— 以上都修好仍录不进，是 macOS 隐私权限没给；App 完全退出重开即生效。
